# Память проекта: proj_8805

## Проект: Weather WebView (Android, погода)
- Стек: Java + платформенный `android.webkit.WebView`, без Kotlin/AndroidX/внешних зависимостей.
- UI: единый `app/src/main/assets/weather.html` (HTML/CSS/JS, офлайн, без CDN).
- Сеть: `HttpURLConnection` в `WeatherBridge.java`, только HTTPS (Open-Meteo, ключ не нужен).
- Связь: `addJavascriptInterface(bridge, "Native")`; JS вызывает `requestForecast/searchCity/locate`, нативный код шлёт JSON через `window.__onNativeData`.
- Acceptance: `file:///android_asset/weather.html`, `allowUniversalAccessFromFileURLs=false`, `cleartextTrafficPermitted=false`.
- Геолокация: `ACCESS_COARSE/FINE_LOCATION`, `getLastKnownLocation`, фолбэк на поиск города.
- Иконки: PNG по плотностям (API 23-25) + adaptive-icon только в `mipmap-anydpi-v26`.

## Тулинг / CI
- AGP 8.5.2, Gradle 8.7, JDK 17, compileSdk/targetSdk 34, minSdk 23, build-tools 34.0.0.
- Gradle wrapper НЕ лежит в репо: CI ставит Gradle через `gradle/actions/setup-gradle@v4` (`validate-wrappers: false`). Локально Gradle/SDK не скачивать (требование пользователя).
- Workflow: `.github/workflows/android-build.yml`; триггеры push main / тег v* / PR / workflow_dispatch.
- Важный нюанс `android-actions/setup-android@v3`: инпут `packages` делится через `.split(' ')` БЕЗ учёта кавычек и вызывает `sdkmanager` без `install`. Поэтому пакеты ставятся отдельным шагом `sdkmanager --install "platforms;android-34" "build-tools;34.0.0" "platform-tools"`.
- Выход CI: debug + unsigned release APK и SHA256SUMS в артефактах; на теге `v*` — GitHub Release.
- `cache: gradle` в setup-java убран во избежание конфликта с кэшем setup-gradle.
